# API Reference

Base URL when running locally: `http://127.0.0.1:8000`.
Interactive version of this page (generated by FastAPI):
`http://127.0.0.1:8000/docs`.

## Data format

This format was agreed by both teammates. The Pydantic models in
`backend/models.py` enforce it; the limits come from
`backend/config/business_rules.py`.

### Student

```json
{ "id": 1, "name": "Hasan", "topic": "Python", "status": "Active", "score": 80 }
```

| Field    | Type            | Rules                                        |
|----------|-----------------|----------------------------------------------|
| `id`     | integer         | Generated by the database; never sent        |
| `name`   | string          | Required, 1–100 characters, not blank        |
| `topic`  | string          | Required, 1–100 characters, not blank        |
| `status` | string          | `Active`, `Paused` or `Completed`            |
| `score`  | integer or null | 0–100, or `null` when there is no score yet  |

Leading and trailing spaces are removed, so `"   "` counts as blank.

### Summary

```json
{ "total_students": 3, "active_students": 2, "average_score": 76.67 }
```

`average_score` is the NumPy mean of all non-null scores, rounded to
`ACADEMY_AVERAGE_DECIMALS` decimals. It is `null` when no student has a
score; the page then shows "No scores yet."

## Endpoints

| Method | Path                 | Purpose                                 | Success | Owner      |
|--------|----------------------|-----------------------------------------|---------|------------|
| POST   | `/api/students`      | Add a student; returns it with its `id` | 201     | Bahodirjon |
| GET    | `/api/students`      | List students, ordered by `id`          | 200     | Bahodirjon |
| GET    | `/api/students?status=Active` | List only one status           | 200     | Hasan      |
| PATCH  | `/api/students/{id}` | Update `topic`, `status` and/or `score` | 200     | Hasan      |
| GET    | `/api/summary`       | Counts and average score                | 200     | Hasan      |

### PATCH rules

- Send only the fields to change, e.g. `{"score": 95}`.
- At least one field is required; `{}` is rejected.
- `score` may be set to `null` to clear it.
- `topic` and `status` may be left out but not set to `null`.

## Errors

| Status | When                                              | `detail` format                    |
|--------|---------------------------------------------------|------------------------------------|
| 422    | Invalid data (blank name, bad status, score > 100) | List of `{loc, msg, ...}` objects |
| 404    | `PATCH` on an `id` that does not exist            | Text: `"Student 7 not found"`      |

Example 422 response:

```json
{
  "detail": [
    {
      "type": "less_than_equal",
      "loc": ["body", "score"],
      "msg": "Input should be less than or equal to 100",
      "input": 200
    }
  ]
}
```

The page (`frontend/app.js`, `formatErrorDetail`) turns this into
`score: Input should be less than or equal to 100` and shows it in red.
